# Avi Gorodetski — Portfolio

A responsive, multi-page personal and professional portfolio for Avi Gorodetski. The site features work with GiVV, BBYO, TUCP, and other organizations, plus an experience page, a personal introduction, and direct contact links.

## Pages

- `index.html` — introduction and featured work
- `work/index.html` — selected work
- `now/index.html` — curated current work, community, and listening updates
- `work/alphasights/index.html`, `work/givv/index.html`, and the other pages under `work/` — selected experience and project stories
- `about/index.html` — background and interests
- `experience/index.html` — roles, education, and résumé
- `contact/index.html` — email, LinkedIn, and résumé
- `404.html`, `robots.txt`, and (when `SITE_URL` is set) `sitemap.xml` — generated by the build

The supplied headshot, event photography, and résumé are in `assets/`. The copy and page markup live in `build_site.py`, while `styles.css` and `script.js` provide the shared presentation and the mobile menu toggle. Curated update data lives in `updates.json`. The build script writes HTML to the repository root and mirrors the complete static site into `dist/` for Sites hosting. All links and assets use relative URLs, so the site works on a subpath as well as a domain root; the one exception is `404.html`, which uses root-relative links (or the public address when `SITE_URL` is set) because it is served from whatever URL was mistyped.

Two constants at the top of `build_site.py` are worth knowing: `EMAIL` (the contact address used in the footer and on the Contact page) and `SITE_URL` (the public address, with no trailing slash). `SITE_URL` is set to the live GitHub Pages address; change it in this one place if a custom domain replaces it. While it is set, the build adds canonical, `og:url`, and social-preview image tags, writes `sitemap.xml`, and gives `404.html` absolute links so it keeps its styling on a subpath host. If it is ever emptied, those are skipped and `404.html` falls back to root-relative links, which only work on a domain root. Image `width` and `height` attributes are filled in from the real files at build time, and the build exits with an error if any page in the root or `dist/` copy links to a file that does not exist, if an image in `assets/` is truncated or corrupt, or if `updates.json` breaks the rules below.

## Curated updates

`updates.json` is the canonical source for the homepage “Recently” section and the full Now page. The build renders these cards straight into the HTML (no JavaScript or extra request is needed), so **run `python3 build_site.py` after every edit to `updates.json`**; the build also checks the file and stops with a message if an item is malformed. Keep dated milestones newest-first, followed by ongoing items (monthly playlists, LinkedIn, this repository), and keep the list to no more than six items. The homepage shows the first three, so the order is also the priority. Add an item only when it strengthens the professional story or adds a meaningful personal dimension; do not mirror every social post. Each item requires an ISO date (`YYYY-MM-DD`), reader-facing date label, category, title, short summary, source name, and public `https://` source URL. Remove or refresh time-bound items (for example an upcoming event) once their date has passed.

Review these public sources for candidates: Avi's LinkedIn profile, TUCP (`geauxtucp.com` and `@geauxtucp`), GiVV (`@thegivvapp`), Strong City (`mystrongcity.org`), Spotify (`@avigorodetski`), and the GitHub repository. If a source is unavailable, leave the current item unchanged. Never add a claim that cannot be verified against a public source or information Avi has supplied directly. After editing, run the build, confirm the JSON renders on both pages, and publish the resulting `dist/` directory.

## Editing and preview

Run `python3 build_site.py` after changing page content, CSS, or JavaScript. Preview locally with `python3 -m http.server 8000` and open `http://localhost:8000/`. No package installation is required. Commit the regenerated root pages and `dist/` together; a GitHub Actions check (`.github/workflows/check-build.yml`) rebuilds the site and fails if the committed output is out of date.

When adding photos, resize them to roughly 1600 pixels on the long edge and save them as JPEG (around 80% quality) so pages stay light; see the existing files in `assets/` for the target size. The build now rejects a truncated or corrupt JPEG or PNG, which would otherwise “exist” and pass the link check but render as a blank box. (The original Strong City Thanksgiving Drive photo was exactly that, and has been replaced with a fresh export.)

The site uses semantic landmarks, visible keyboard focus, a skip link, reduced-motion support, and a navigation menu that works as ordinary links when JavaScript is unavailable. The mobile menu is collapsed by the stylesheet itself so the page never shifts while loading; a `<noscript>` rule in each page’s `<head>` shows the plain links when JavaScript is off. `apple-touch-icon.png` is a 180px render of the favicon artwork.

## Publishing

The current hosted Site uses `.openai/hosting.json` and the static `dist/` directory. The repository-root pages are also served with GitHub Pages at `https://agorodetski.github.io/portfolio/`, which is the address `SITE_URL` points to.

The Site's audience remains owner-only until its access settings are changed. The contact email is Avi's Tulane address from the résumé; it can be changed in one place (`EMAIL` in `build_site.py`) when a permanent address replaces it. The Spotify handle appears as text because a direct profile URL has not yet been verified.
